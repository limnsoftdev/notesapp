# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

단어장 (Word Log) — a personal Korean vocabulary/phrase log with spaced-repetition flashcard training. Static, no-build, no-dependency PWA: `index.html` + `app.js` + `styles.css`, no framework, no bundler, no package.json.

## Running it

There is no build/test/lint tooling. Open `index.html` directly in a browser, or serve the folder with any static file server (needed for the PWA manifest/service-worker-style behavior to work correctly, e.g. `npx serve` or `python -m http.server`). Changes to `app.js`/`styles.css`/`index.html` take effect on reload — no compile step. `index.html` loads them with a `?v=` version tag: bump it whenever those files change, or browsers can pair a new `index.html` with a cached old script and break.

## Architecture (all logic lives in `app.js`, organized in commented sections)

**Data model & persistence** — everything is `localStorage`, no backend/server:
- `koWordLog.v1` — the `entries` array, each `{ id, korean, romanized, meaning, category, createdAt, srs }`
- `koWordLog.settings.v1` — theme/sort/dailyGoal/API keys
- `koWordLog.streak.v1`, `koWordLog.daily.v1` — streak and daily-goal tracking
- `migrateSrs()` backfills the `srs` field for entries created before spaced-repetition was added; runs on every load and after backup import, so new persisted fields need a similar migration guard rather than assuming all entries have them.

**Add flow** (`handleAdd`) — one input accepts either Korean or English. It detects which via `hasHangul()`, then:
1. Romanizes Korean input locally via a hand-rolled Revised Romanization implementation (`romanize`/`decompose`, no library) — handles syllable-final consonant linking onto a following null-onset syllable.
2. Auto-translates the other direction using MyMemory's free API (`translate()`, no key required).
3. If translation fails, falls back to `openManualRow()` for manual entry rather than blocking the add.
4. Auto-categorizes the entry from its English meaning via whole-word regex matching against `CATEGORY_KEYWORDS` (`autoCategorize`) — deliberately word-boundary (`\b...\b`), not substring, since substring matching previously miscategorized "money" as "numbers" via "one".

**Training / spaced repetition** — a Leitner-box system (`BOX_INTERVALS`, `applySrsRating`): wrong answers reset to box 0 and are requeued once within the same session; correct answers advance a box and push `dueAt` further out. Grading is self-reported (user clicks "got it"/"not quite") rather than string-matched, since free-form translations have too many valid phrasings to auto-grade. A training session (`session` object: `queue`/`index`/`tally`/`requeued`) is built by `buildSessionQueue()`, prioritizing due cards.

**Rating moment** (`playRatingMoment`) — the SRS result is saved first, then the animation plays: a stamp lands in the card's top-right corner (empty once the answer shows, so it hides no text) and the memory dots change, then a clone of the card flies off (right = got it, left = not quite) while the real card, already holding the next word, rises behind it. About 700ms in total. It uses Web Animations rather than GSAP so it works if the CDN fails, and `setTimeout` for sequencing so a backgrounded tab can't strand a session. Because script animations ignore the global reduced-motion CSS rule, it checks `prefers-reduced-motion` itself and shows the same stamp and dots with no travel. `clearRateFx()` abandons a moment in flight (ending a session, starting a new one).

**Speech** (`speak`) — uses the browser's `speechSynthesis`, so it needs a Korean voice on the device. With none, English voices "read" hangul as silence and report success, so that case shows a toast instead of trying. Chrome can drop a `speak()` made right after `cancel()` and stay stuck on `speaking=true`, so a busy queue waits `SPEAK_SETTLE_MS` first, and a start watchdog retries once. An idle tap must call `speak()` synchronously (iOS requires it inside the gesture). Google's `translate_tts` is not a usable fallback: Chrome's Opaque Response Blocking rejects it, and don't route it through a public proxy.

**Enrichment on answer reveal** (`revealCard`) — two independent, best-effort, non-blocking fetches keyed off `ratingRow.dataset.entryId` so a slow response arriving after the user has moved to the next card is discarded:
- Word GIF via Klipy's `gifs/search` endpoint (Tenor's replacement; Tenor shut down 2026-06-30) — requires a user-supplied API key stored in settings. `findMediaUrl()` walks the response recursively looking for an image/video URL instead of hardcoding a field path, because Klipy's exact response shape isn't fully documented.
- Example sentence via Tatoeba first (no key, returns matched KO/EN pairs directly), falling back to KRDict (needs a user key, XML response, Korean-only — its English gloss is produced by running the result through the same `translate()` helper).

API keys (Klipy, KRDict) are stored in `localStorage` only, never sent anywhere but the respective API. The settings UI flags keys containing non-ASCII characters as likely mangled by mobile autocorrect/autocapitalize.

**Rendering** — no framework; `renderLog()`/`renderChips()`/`buildEntryCard()` rebuild DOM from the `entries` array on every mutation. All user-provided text is inserted via `escapeHtml()` before going into `innerHTML` — preserve this when touching card rendering or edit-mode markup.

**UI is built around memory strength** — an entry's Leitner box (0–5) is shown everywhere as a 5-dot meter plus a status (`statusOf()`: new / fading / back in N days). The log defaults to `fading` sort (`fadingOrder()`: due reviewed words weakest-first, then new, then by return date); the first chip cycles the sort. A banner (`renderFadeBanner()`, refreshed from `updateDueDot()`) offers a one-tap review of what's due. Edit/delete sit behind each card's ⋯ menu. The streak flame's ring is the daily goal (`renderDaily()`). During a session `.app.in-session` hides the header/banner/tabs; rating buttons show what each choice does (`daysText()` of the next box interval). The summary lists each word's strength change from `session.results`. Example sentences use `findWord()` so short words only match as whole words (물 must not match 물러서). Select & share is launched from settings. Fonts: Inter for UI, Noto Sans KR for Korean, and Titan One (`fonts/`, OFL) only for the "daneo" logo in the study world.

**Theming** — `applyTheme()` sets `data-theme="light|dark"` on `<html>` (or follows `prefers-color-scheme` when set to `auto`); `styles.css` defines colour tokens on `:root` and redefines them under `:root[data-theme="dark"]` (dark mode has real dark cards). Light mode's ground is the brand blue with white cards; both have the same hills along the bottom as the foyer.

**Study** (`study.js` and `study-lessons.js`, loaded after `foyer.js` and the course files; progress in `koWordLog.study.v1`, included in backups) — test-prep courses, and deliberately a separate world from the word log. The topbar's `#worldSwitch` flips between them: `html.world-study` swaps in its own green color tokens and hides the streak ring, fading banner and tabbar. Study has its own day streak (`markStudied`), and no points system: XP was tried and removed because it unlocked nothing and must never call the word log's `bumpDaily`/`bumpStreak`; `switchTab` calls `leaveStudy()`, and waking Danno reopens the last world (`openLastWorld`). Each course has three sections: learn (a path built by `pathStops`: each unit's lessons, a practice stop, then the final mock), practice and test. Lessons (`courses/lessons-*.js`, one file per course on `window.STUDY_LESSONS`) teach before testing, with steps of type teach, stages (a visual stepped through), order, match, sort, widget and q (a bank question by id). Visuals and widgets are code (`VISUALS`, `WIDGETS` in `study-lessons.js`) drawn with theme tokens; lesson text is plain and only supports `**bold**`. Path stops are one upright shape everywhere, sized from tokens (`--stop-w`, `--stop-face`, `--stop-wall`): a wide face over an even `box-shadow` wall that compresses on press. Don't rotate them with `perspective`, which skews each side differently and warps the icon. Danno sits on the current one (`knees.png`) and hops onward after a lesson (`pathHopFrom`). Answers in practice and lessons bring up `resultSheet` and `playAnswerFx` (burst, Danno's reaction, confetti at a 3-in-a-row streak); mock tests deliberately stay silent like the real thing. On a streak the progress bar reacts subtly (`study-streak.js`, `streakBar.set(streak, session)` after every redraw): the gold warms to amber, a soft shine sweeps across it, it bounces on each right answer and the fill slides forward. The count appears in the result sheet, never over the bar. A burning-bar effect was tried in several styles and rejected, so keep this understated. Script animations ignore the global reduced-motion CSS rule, so each effect checks `motionAllowed()`. Vary Danno's pose by moment (stand when happy, peek when curious, knees when it went badly) rather than reusing one. A course is plain data in `courses/*.js`, pushed onto `window.STUDY_COURSES`, so adding one needs no code and user-made courses stay possible later. Each question is `[id, objective, text, [correct, ...3 wrong], explanation]`: the unit is the id's prefix, the correct option is always authored first and shuffled on display, and ids must never be renumbered because progress is stored against them. Unit weights must add up to `exam.questions`. Practice grades itself and explains each answer, and a miss returns once in the same run. Mocks split questions by the real test's unit weights, run on an absolute `endsAt` so the clock keeps going if you leave, save every answer to survive a closed app, and grade on return if time ran out. All answers feed the same Leitner intervals as words. Questions are original and written to published objectives: never copy real test items in, and never present a practice score as a prediction.

**AP courses** (`study-ap.js`, `study-grading.js`, `courses/ap-world.js`, `courses/lessons-apw.js`) — a course with `unitPicker: true` opens on a unit list, and `study.unitFocus[courseId]` keeps everything inside the chosen unit; FBLA courses don't set it and behave as before. A unit with no questions shows as "coming soon", so adding a unit is data only. The exam format follows the course framework effective fall 2026 (May 2027 exam: 3 required SAQs that each have a source, 1 required LEQ with no choice of prompt); older prep material describes a different format. Questions can name a source as an optional sixth field, and `pickUnitTest` keeps a source's questions together like the exam's sets. Cards (`course.cards`) are image, clue, answer, then a sentence showing how to use the fact in an essay, on the same Leitner intervals under `<course>:card:<id>`, and self-graded in one tap like word training. Lessons with `track: 'write'` appear in the write tab, not on the path, and mostly grade themselves through `pick` and `recall` steps. Written responses go only through `gradeResponse()`: the default grader is a keyword auto-check that *suggests* each rubric row and can't judge an argument, so the student confirms every row and it's labeled a suggested score. AI grading was deliberately deferred: add one entry to `GRADERS`, and never put an API key in this public code (friends sharing a key need a small server). Images are hand-picked from Wikimedia Commons, bundled in `images/apwh/`, checked by eye and credited with their license; don't use live GIF search here because it returns the wrong things. Primary sources are public-domain translations quoted exactly, secondary-style passages must be labeled as written for this app, and nothing is copied from AMSCO or real AP exams.

**Feedback** (`fx.js`, loaded last) — the rule: when you click something, something happens right away. Every button in the app squishes on press. A ring at the tap point was tried and removed, so don't bring it back. Disabled action buttons shake when tapped, because "not yet" is still a response. Screens add their own moments on top: slides by direction (`screenFx`), one sliding thumb for tabs, a flip when a card's answer shows and a fly-off when it's rated, a score that counts up. A redraw that only updates a screen in place must use `.still` so the entrance doesn't replay. Mock tests confirm a selection but stay silent about whether it's right. Everything checks `motionAllowed()`. New interactive things need a visible response, including the case where the action can't happen yet.

**The two worlds' logos** — the word log is 단어장, and the study world is "daneo" in Titan One. Both logos sit in one grid cell so nothing shifts, and CSS picks by `html.world-study`, so every way of changing worlds is correct without animation. Tapping the switch also runs `changeWorld`: the new world's color spreads from the button, screens swap once it covers them, and `morphLogo` plays the name's meaning (dan-eo-jang: 장 falls off, and 단 and 어 flip into "dan" and "eo"). The foyer always says 단어장, since it's the app's name.

**Voice** (`voice.js`, loaded after `fx.js`) — the word log's main action is one big centered mic, laid out like a camera's shutter with two quiet helpers beside it: language on the left, keyboard on the right (the type field stays hidden until asked for). Nothing moves until you touch it: continuous pulses, sound waves and a full-width slab were all tried and rejected. A line (`.voice-arch`) comes in from each screen edge, rises in an arch concentric with the mic and goes back down, with a tint fading out below it, so the mic reads as attached to the content under it. It uses the browser's `SpeechRecognition`: the session runs one language and can't detect it, so a remembered 한국어/English switch (`settings.voiceLang`) picks, and without recognition the mic stays hidden. `start()` must run directly inside the tap. Guesses appear live while you talk, then the sheet asks "do you mean 핫도그?" (English) or "did you say 사과?" (Korean), and English is always added as Korean. The confirmation is the point of the feature: "yes, that's it!" lands a check and Danno's reaction before the word leaves, so keep that beat. If no translation comes back, the fields open for filling in rather than losing the word. Every add, voice or typed, goes through `commitEntry` and `landEntry`, which flies the new card from where it came from to its place while the others make room.

**Foyer** (`foyer.js`, loaded after `app.js` and using its globals; GSAP from cdnjs) — the welcome screen shown on every open and when the topbar logo is tapped. The app is for retention, so it leads with what's fading: the due count, a "review now" button that starts a session directly, and one quick rep on the due word with the lowest box (rating it goes through `applySrsRating`/`bumpDaily`/`bumpStreak` like a training card). Every open starts with only Danno asleep (`.is-asleep` is set in the markup so the first paint is right, and the rest of the foyer is `display:none` so he stays centred); tapping him *is* logging in: 단어장 rises out of a blur syllable by syllable, he hops to his feet, then the wipe goes straight into the log (beat timings are listed above `wakeUp()`). The logo keeps its space while hidden so Danno never shifts. The foyer's greeting, quick rep and buttons only show when returning via the topbar logo (short entrance). Coming back to the app after more than a minute away (`visibilitychange`, `AWAY_MS`) puts Danno back to sleep, so every visit starts with tapping him; waking him then returns you to the view you left instead of the log. Tapping awake Danno makes him hop or peek. Leaving the foyer is a two-tone wipe: a gold band then a paper band with rounded ends sweep left to right across the screen and off the other side (transform-only); the app is swapped in while the paper band covers everything. Danno's idle breathing is a CSS animation (`.danno.idle`), not a GSAP `repeat: -1` tween: infinite tweens crash Chrome when the global timeline is retimed. Danno is the real drawings from the character sheet, one PNG per pose in `danno/` on a shared 300×500 canvas with feet on the same baseline. Pose swaps are instant, so always hide them inside fast motion (a squash or the top of a hop). Respects `prefers-reduced-motion`.

## Notes from recent history

- Category matching must stay word-boundary, not substring (see `CATEGORY_PATTERNS`).
- Klipy is the current GIF provider; don't reintroduce Tenor.
- Backup export/import (`exportBackupBtn`/`importBackupBtn`) is the only migration/portability path — it round-trips the full `entries` array as JSON and merges by `id` on import, prompting to merge vs. replace when IDs collide.
